# ЛР3. Многоагентное распределение частоты поездов метро Нью-Йорка

Дисциплина «Прикладные задачи машинного обучения». Лабораторная работа 3.

**Тема ВКР:** «Разработка модели динамического прогнозирования спроса на городской транспорт
с учётом пространственных и временных зависимостей».

**Задача.** Каждый час 8 агентов (группы линий метро: 1·2·3, 4·5·6, 7, A·C·E, B·D·F·M, N·Q·R·W, J·Z·L, G) решают,
сколько поездов выпускать относительно расписания MTA (0,7…1,3), а агент-координатор задаёт часовой лимит
поездов в работе. Бюджет поездо-часов на сутки равен расписанию. Цель — меньше потерь времени пассажиров
(ожидание, неуспевшие сесть, теснота) **теми же ресурсами**. Спрос — реальные почасовые входы 424 станций
(данные ВКР), расписание — реальное, с поправками на плановые работы.

Сравниваются 8 MARL-алгоритмов (IPPO, MAPPO, HAPPO, MAT, COMA, MADDPG, VDN, QMIX) при одинаковых бюджете
взаимодействий, разбиении и seed. Контрольные baseline — расписание MTA и одноагентный PPO. Дополнительные
неучащиеся эталоны — MPC «прогноз + оптимизация» и оракул. **Связь с ВКР:** прогноз спроса из ВКР входит в
наблюдение агентов и в MPC; лестница прогнозов переводит точность прогноза (WAPE) в сэкономленные
пассажиро-часы.

Протокол зафиксирован до запуска: [`PROTOCOL.md`](PROTOCOL.md). Спецификация среды:
[`report/env_spec.md`](report/env_spec.md). Обзор литературы: [`report/literature_review.md`](report/literature_review.md).

## Структура

```
PROTOCOL.md            протокол (до запуска) и журнал отступлений
marl_env.py            среда: данные, модель потерь, защитный слой, наблюдения, расписание, MPC, оракул
marl_data.py           подготовка данных: датасет ВКР + расписания MTA (data.ny.gov) → env_data.npz
marl_algos.py          8 MARL + одноагентный PPO (PyTorch, CPU), общий цикл обучения и выбор чекпойнта
marl_eval.py           метрики, бутстреп-ДИ, сводный балл и выбор, кооперация, стресс-тест, параллельный запуск
notebooks/             ноутбуки для Kaggle (собираются из notebooks/src/*.py: python notebooks/src/build_notebooks.py)
report/                обзор литературы, спецификация среды, отчёт, карточка рисков
results/               выводы ноутбуков, скачанные с Kaggle (по папке на ноутбук)
tests/                 синтетические данные той же формы и сквозной прогон всех ноутбуков (только отладка)
```

## Как запустить на Kaggle

Каждый ноутбук: **File → Import Notebook** → `.ipynb` → справа **Add Input** → **Save Version (Save & Run All)**.
Затем скачать **Output** в `results/<имя ноутбука>/`. Везде Accelerator — **нет** (CPU): сети маленькие,
прогоны идут в параллельных процессах по числу ядер.

| № | Ноутбук | Internet | Inputs | Время (оценка) |
| --- | --- | --- | --- | --- |
| 1 | `lab3_00_data` | **да** | `VKR_PM232_Pevin_MTA`; *необязательно* вывод ноутбука 16 ВКР (`hyb_blend__val.npz`, `hyb_blend__test.npz`) | 40–70 мин |
| 2 | `lab3_01_tune` | нет | вывод `lab3-00-data` | 30–60 мин |
| 3 | `lab3_02_main_onpolicy` | нет | выводы `lab3-00-data`, `lab3-01-tune` | 1–2 ч |
| 4 | `lab3_02_main_offpolicy` | нет | выводы `lab3-00-data`, `lab3-01-tune` | 1–2 ч |
| 5 | `lab3_03_select` | нет | выводы `lab3-00-data`, оба `lab3-02-main-*` | ~10 мин |
| 6 | `lab3_04_apply` | нет | выводы `lab3-00-data`, `lab3-01-tune`, `lab3-03-select` | 1–3 ч |
| 7 | `lab3_05_summary` | нет | выводы **всех** ноутбуков выше | 30–60 мин |
| 8 | `lab3_06_hard_budget` | нет | выводы `lab3-00-data`, оба `lab3-02-main-*`, `lab3-03-select`, `lab3-04-apply` | 20–40 мин |

Ноутбуки 3 и 4 независимы и могут идти параллельно. Если ноутбук 16 ВКР не подключён, всё работает, но в
лестнице прогнозов не будет ступени «гибрид ВКР» (это запишется в паспорт).
