# ЛР3. Протокол: многоагентное распределение частоты поездов метро Нью-Йорка

Протокол зафиксирован **до** запуска алгоритмов на реальных данных (06.11.2026). Код отлажен на синтетических
данных той же формы (`tests/`), цифры синтетики в отчёт не идут. Отступления записываются в разд. 14 с датой и
причиной; результаты до отступления не удаляются. Работа выполняется индивидуально.

## 0. Как задание переложено на нашу задачу

Задание сформулировано на финансовом примере (агенты-секторы управляют весами портфеля, пятый агент
ограничивает риск). Мы делаем то же на данных ВКР — метро Нью-Йорка:

| Задание (финансы) | ЛР3 (метро) |
| --- | --- |
| OHLCV, аудит котировок | почасовые входы 424 станций (ВКР) + расписания MTA с поправками (data.ny.gov) |
| признаки только из прошлого | прогноз спроса и наблюдения — только по часам < h; расписание публикуется заранее |
| актив / сектор | группа линий (магистраль): 1·2·3, 4·5·6, 7, A·C·E, B·D·F·M, N·Q·R·W, J·Z·L, G |
| 4 агента-сектора + агент риска | 8 агентов линий + координатор парка (часовой лимит поездов в работе) |
| действие — целевой вес | множитель к расписанию 0,70…1,30 (5 уровней); координатор — лимит 0,85…1,15 |
| вознаграждение: лог-доходность − комиссия − штраф риска | −потери времени пассажиров (доля от расписания) − штраф за смену частоты − штраф за перерасход бюджета |
| транзакционные издержки | поездо-часы и смена частоты (оборот) |
| лимит концентрации | защитный слой: нормативный интервал, пропускная способность, лимит парка |
| равновзвешенный портфель | расписание MTA без изменений |
| одноагентный PPO | одноагентный PPO, управляющий всеми группами сразу |
| сектор, связанный с ВКР (задание 4) | отложенный свежий период + перенос на подсеть (дивизион A / дивизион B) |
| доходность, Sharpe, Sortino, просадка, CVaR | выигрыш к расписанию, IR, Sortino, худшие сутки, CVaR 5% худших суток |

**Связь с ВКР.** ВКР строит прогноз спроса; ЛР3 отвечает на вопрос, *сколько стоит точность прогноза в
решениях*. Прогноз ВКР входит в наблюдение агентов и в MPC-планировщик; лестница прогнозов (медиана 4 недель →
norm_level → гибрид ВКР → оракул) переводит WAPE в пассажиро-минуты (гипотеза H6).

## 1. Постановка

Dec-POMDP с общей наградой, 9 агентов, шаг 1 час, эпизод — сутки (24 шага). Полная спецификация:
`report/env_spec.md`. Бюджет поездо-часов на сутки = расписание: сравнение «те же ресурсы — лучше распределены?».

## 2. Данные и разбиение

| часть | период | назначение |
| --- | --- | --- |
| история | 01.01–29.01.2023 | только для прогноза «норма» (4 недели) |
| train | 30.01.2023 – 31.03.2026 | обучение политик, коэффициенты norm_level, калибровка наполнения |
| val | 01.04 – 30.06.2026 | подбор скорости обучения, выбор чекпойнта, выбор алгоритма |
| test | 01.07 – 24.09.2026 | главная таблица сравнения, один раз |
| holdout | 25.09.2026 – последний полный день выгрузки MTA | полностью отложенный период (задание 4) |

Разбиение совпадает с ВКР (гибрид ВКР обучен до 31.03.2026, его прогнозы на val/test честные). Holdout —
свежие данные, скачанные в `lab3_00_data`; в момент фиксации протокола их никто не видел.

Предобработка (`marl_data.py`), каждое решение — в паспорте данных:
- полная сетка часов (весенний перевод — интерполяция одного часа);
- входы станции делятся между группами её маршрутов пропорционально поездам по расписанию; станции только
  с челноками выпадают;
- расписание: отправления с начальной станции (stop_order = 1) по часам; сутки без расписания — типичное
  расписание по типу дня из train (флаг `schedule_filled`);
- время оборота — по датам-образцам (2-я среда и 2-я суббота каждого квартала).

Состояние, действия, переходы, награда, ограничения, издержки и завершение эпизода — `report/env_spec.md`.

## 4. Параметры среды (фиксированы)

| параметр | значение | обоснование |
| --- | --- | --- |
| калибровка наполнения ρ в типичный будний пик по расписанию | 0,90 | нормативы MTA: расписание составляется так, чтобы в пик не превышать норматив; 0,9 — запас; чувствительность — стресс S5 |
| начало штрафа тесноты ρ₀ | 0,60 | примерно все сидят; ниже теснота не ощущается |
| физический предел посадки ρ_max | 1,35 | 135% норматива; сверх — пассажир ждёт следующий поезд |
| эффективная поездка в зоне макс. загрузки | 10 мин | доля типичной поездки, проходящая через самый загруженный участок |
| нормативный интервал | ≤ 20 мин на работающую линию | минимальный уровень обслуживания |
| запас парка | 5% сверх пикового выпуска по расписанию | резервные составы |
| λ_B (перерасход бюджета) | 5 | 1% перерасхода = 5% суточных потерь: перерасход невыгоден |
| λ_sw (смена частоты) | 0,1 | смена частоты требует перестановки составов и бригад |
| диапазон действий | 0,70…1,30 расписания | резерв составов и бригад в пределах суток |

Числа калибровки не подбираются по результатам — это допущения, и их чувствительность проверяется (S5).

## 5. Алгоритмы и единый протокол сравнения

**8 MARL:** IPPO, MAPPO, HAPPO, MAT, COMA, MADDPG (Gumbel-Softmax), VDN, QMIX.
**Контрольные baseline (2, обязательны по заданию):** расписание MTA; одноагентный PPO (вход — полное
состояние, действие факторизовано по 9 агентам).
**Дополнительные эталоны (не учатся):** MPC «прогноз + оптимизация до конца суток» с прогнозами m4w / norm_level /
гибрид ВКР; оракул (MPC с фактическим спросом) — верхняя граница в том же пространстве действий.

Одинаково для всех учащихся алгоритмов:
- среда, наблюдения, состояние, награда, набор суток train;
- **бюджет взаимодействий — 400 000 шагов среды** (≈ 16 700 суточных эпизодов);
- сети 2 × 128 с LayerNorm на входе (у MAT — трансформер d = 64 сопоставимого размера);
- **seed 0, 1, 2, 3, 4** для итоговых прогонов;
- **подбор:** скорость обучения ∈ {по умолчанию, по умолчанию / 3} (для акторов и критиков одновременно),
  seed 100, половина бюджета (200 000 шагов), выбор по лучшей средней награде на val. Остальные гиперпараметры —
  по умолчанию из исходных работ и библиотек (MAPPO, PyMARL) — `marl_algos.DEFAULTS`;
- **чекпойнт:** 12 оценок на val за прогон (детерминированная политика), берётся лучший по средней награде;
- оценка — детерминированная политика (argmax), одна и та же функция `marl_env.rollout`.

## 6. Метрики (направление улучшения зафиксировано заранее)

Суточный выигрыш `gain(d) = 1 − J_политики(d) / J_расписания(d)` (J — потери пассажиро-минут).

| метрика | аналог в задании | лучше |
| --- | --- | --- |
| выигрыш, % (среднее по суткам) | доходность | больше |
| IR = среднее / ст. откл. суточного выигрыша | Sharpe | больше |
| Sortino = среднее / нижнее отклонение | Sortino | больше |
| худшие сутки, % | максимальная просадка | больше |
| CVaR: средний выигрыш в 5% худших суток | CVaR 95% | больше |
| потери и ожидание, мин/пассажира | — | меньше |
| пассажиров в переполненных поездах (ρ > 1), % | риск | меньше |
| часы выше норматива, % «группа × час» | нарушения лимитов | меньше |
| перерасход бюджета > 0,5%, % суток | нарушения лимитов | меньше |
| вмешательства защитного слоя, % решений | нарушения лимитов | меньше |
| оборот: Σ|изменение отклонения| / бюджет, % в сутки | оборот | меньше |
| поездо-часы, % бюджета | издержки | ≤ 100 |
| ст. откл. выигрыша по seed | устойчивость по seed | меньше |
| кооперация: вклад агентов (замена расписанием), синергия, перераспределение, согласованность | кооперация агентов | — (описательно) |
| время обучения, мс на решение, параметров | вычислительная стоимость | меньше |

## 7. Правило выбора лучшего алгоритма (по val, тест не смотрим)

1. **Допуск:** перерасход бюджета ≤ 2% суток и нижняя граница 95% ДИ выигрыша > 0.
2. **Сводный балл** по метрикам, нормированным min–max среди 8 MARL + PPO:
   35% выигрыш, 20% IR, 20% CVaR, 10% доля пассажиров в переполненных поездах, 10% оборот,
   5% ст. откл. выигрыша по seed.
3. **Простота:** если более простой алгоритм (порядок: IPPO < VDN < MAPPO < PPO < QMIX < MADDPG < COMA <
   HAPPO < MAT) отстаёт по баллу не больше чем на 0,10 и разница выигрыша с лидером незначима (ДИ содержит 0),
   выбирается более простой.

Одноагентный PPO участвует в сравнении, но «лучшим MARL» быть не может; если PPO лучше всех MARL, это отдельный
вывод (H3).

## 8. Гипотезы (до запуска)

- **H1 (CTDE).** MAPPO лучше IPPO по выигрышу на test (парная разница > 0, ДИ не содержит 0).
- **H2 (MARL против расписания).** Выбранный алгоритм даёт выигрыш > 0 на test (нижняя граница ДИ > 0) и на holdout.
- **H3 (MARL против одного агента).** Выбранный MARL не хуже одноагентного PPO больше чем на 1 п.п. выигрыша на test.
- **H4 (координатор).** Без координатора сводный балл ниже (выигрыш меньше или нарушений больше).
- **H5 (сообщения).** Без обмена сообщениями выигрыш меньше.
- **H6 (ценность прогноза ВКР).** (а) Для MPC выигрыш растёт с точностью прогноза: m4w < norm_level < гибрид
  ВКР < оракул; (б) выбранный алгоритм без прогноза в наблюдении хуже, чем с прогнозом norm_level; (в) оценка
  «п.п. выигрыша на 1 п.п. WAPE» по лестнице прогнозов.
- **H7 (RL против оптимизации).** Сравнение выбранного MARL с MPC на том же прогнозе (norm_level). Направление
  заранее не задаётся: это проверка того, нужен ли RL сверх «прогноз + оптимизация».

Множественные сравнения: для H1–H5 и H6(б) приводятся сырые p и поправка Холма.

## 9. Абляции, стресс-тест, режимы

**Абляции** (выбранный алгоритм, 5 seed, тот же бюджет и гиперпараметры): A1 без координатора; A2 без
сообщений; A3 без штрафа за смену частоты; A4 без прогноза в наблюдении; A5 прогноз-оракул в наблюдении.

**Стресс-тест** (без переобучения, test; выбранный алгоритм × 5 seed, расписание, PPO, MPC norm_level):
S1 непредвиденный всплеск +40% на одной группе 17–21 ч; S1b тот же всплеск, известный заранее; S2 непогода −40%
спроса; S3 нехватка парка −15% и бюджета −10%; S4 прогноз занижен на 25%; S5 наполнение на 25% выше калибровки.

**Режимы** (test + holdout): будни, выходные, праздники, дни плановых работ (по расписанию < 80% обычного
не меньше 3 ч на группе), городские события. Для каждого — выигрыш с ДИ, чтобы показать, где политика деградирует.

## 10. Применение лучшей политики (задание 4)

1. **Полностью отложенный период** (holdout): выбранная политика (5 seed) без изменений, расписание, PPO, MPC.
2. **Подсеть, связанная с ВКР:** отдельные среды «дивизион A» (1·2·3, 4·5·6, 7 + координатор) и «дивизион B»
   (A·C·E, B·D·F·M, N·Q·R·W, J·Z·L, G + координатор) с долей парка пропорционально пиковому выпуску.
   Выбранный алгоритм и PPO переобучаются **с теми же гиперпараметрами** (без подбора), 5 seed; оценка на test
   и holdout против расписания и MPC.

## 11. Статистика

- 95% ДИ среднего выигрыша — стратифицированный бутстреп (2000 повторов): seed с возвращением × недельные блоки
  суток с возвращением (автокорреляция внутри недели).
- Парные сравнения политик — разница суточных выигрышей (средних по seed), блочный бутстреп по неделям,
  двусторонний p.
- **Статистический против экономического эффекта (задание 6).** Экономически значимым заранее считаем выигрыш
  ≥ 1% потерь времени пассажиров при перерасходе бюджета ≤ 0,5%; в отчёте выигрыш переводится в
  пассажиро-часы в сутки. Статистически значимый, но < 1% эффект — «есть, но практически мал».
